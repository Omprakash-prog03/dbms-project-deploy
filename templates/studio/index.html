Why this session is read-only

        
      

      

        
A database client that can run anything is a database client that can break anything. This one is a teaching simulation, so the rules are drawn where they keep the portal safe:

        
    
          
  • SELECT, WITH, VALUES, TABLE, EXPLAIN run for real, against the live rows.
    • 
          
  • INSERT, UPDATE, DELETE are compiled by the engine and reported as prepared, then declined — you see whether the statement is valid without changing a row.
    • 
          
  • DROP, ALTER, CREATE, PRAGMA, COMMIT, ROLLBACK and the rest are refused, because a typo there would damage the schema or the session.
    • 
          
  • The two append-only registers — sign-in history and the change log — cannot be written from any client, including this one.
    • 
        

        
To change data, use the portal screens, or the SQL console at /raw-data/query, which runs data changes and commits them.
